# POST-QUANTAM

Production-oriented PQC control-plane API.

## Package and run locally

```bash
cd backend
python -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
pip install -e '.[dev]'
cp .env.example .env
# Generate values; do not use development defaults in production.
python -c 'import secrets; print(secrets.token_urlsafe(48))'
python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'

pqctool serve --host 127.0.0.1 --port 8000 --reload
pytest -q
```

The API documentation is generated by FastAPI:

- Swagger UI: `http://127.0.0.1:8000/docs`
- ReDoc: `http://127.0.0.1:8000/redoc`
- OpenAPI JSON: `http://127.0.0.1:8000/openapi.json`

## Environment

Required in production:

- `PQ_ENV=production`
- `PQ_AUTH_SECRET`: long random JWT signing secret
- `PQ_MASTER_KEY`: Fernet key protecting stored private-key material
- `PQ_ADMIN_PASSWORD`: initial administrator password; rotate it after bootstrap
- `PQ_DATABASE` and `PQ_CA_STATE`: durable, restricted storage paths

`PQ_CORS_ORIGINS` must be an explicit comma-separated allowlist. Do not use `*` with credentials.

## API examples

Login:

```bash
TOKEN=$(curl -s http://127.0.0.1:8000/auth/login \
  -H 'content-type: application/json' \
  -d '{"username":"admin","password":"YOUR_PASSWORD"}' | jq -r .access_token)
```

Capabilities:

```bash
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8000/v1/capabilities
```

Generate an ML-KEM key, encapsulate, and decapsulate:

```bash
KEY=$(curl -s -X POST http://127.0.0.1:8000/v1/kem/keys \
  -H "Authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"algorithm":"ML-KEM-768"}')
KEY_ID=$(echo "$KEY" | jq -r .key_id)
ENC=$(curl -s -X POST http://127.0.0.1:8000/v1/kem/encapsulate \
  -H "Authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d "{\"key_id\":\"$KEY_ID\"}")
CIPHERTEXT=$(echo "$ENC" | jq -r .ciphertext)
curl -s -X POST http://127.0.0.1:8000/v1/kem/decapsulate \
  -H "Authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d "{\"key_id\":\"$KEY_ID\",\"ciphertext\":\"$CIPHERTEXT\"}"
```

Certificate lifecycle:

```bash
curl -s -X POST http://127.0.0.1:8000/v1/pki/certificates \
  -H "Authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"subject":"api.example.internal","days":90}'

curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8000/v1/pki/certificates
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8000/v1/pki/crl.pem
```

## Docker Compose

```bash
cp backend/.env.example backend/.env
# Fill every production secret in backend/.env.
docker compose build --no-cache
docker compose up -d
curl http://127.0.0.1:8000/healthz
docker compose logs -f api
```

The container runs as an unprivileged user, drops Linux capabilities, uses a read-only root filesystem, persists only `/var/lib/post-quantam`, and binds the development port to loopback. Put a TLS reverse proxy or service mesh in front of it.

## Production deployment checklist

- [ ] Use a managed secret store or HSM/KMS for `PQ_AUTH_SECRET` and `PQ_MASTER_KEY`.
- [ ] Replace the development CA implementation with an audited CA/HSM integration.
- [ ] Use TLS/mTLS at the ingress and disable direct public access to port 8000.
- [ ] Change the bootstrap administrator password and create named users with least-privilege roles.
- [ ] Restrict `PQ_CORS_ORIGINS` to the actual dashboard origin.
- [ ] Back up the SQLite database and CA state with encrypted, tested backups; use a managed database for high availability.
- [ ] Configure log shipping and protect audit exports from tampering.
- [ ] Do not expose shared secrets from KEM endpoints in a production protocol; derive session keys internally with a reviewed KDF.
- [ ] Install and pin a reviewed liboqs/liboqs-python build; verify enabled algorithms at startup.
- [ ] Run migrations as a controlled deployment step and take a backup first.
- [ ] Scan images and dependencies, sign release artifacts, and enable image provenance checks.
- [ ] Set resource limits, rate limits, request-size limits, and an external WAF/API gateway.
- [ ] Establish CRL/OCSP publication and monitor certificate expiry and rotation failures.
- [ ] Perform an independent cryptographic, application-security, and operational review.
